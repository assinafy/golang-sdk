# Assinafy API v1 mapping

This reference maps the Assinafy Go SDK to all 118 operations in the [API documentation](https://api.assinafy.com.br/v1/docs) and OpenAPI `3.0.0` [description](https://api.assinafy.com.br/v1/docs/openapi.json) for API version `1.0.0`.

## Conventions

- Paths include `/v1` as shown by the API. SDK resource methods use paths relative to `ClientOptions.BaseURL`, which already includes `/v1`.
- Every `{name}` in a path is a required string path parameter. Passing an empty account ID to an account-scoped SDK method uses `ClientOptions.AccountID`.
- `*` marks a required body field. `?` marks an optional body or query field. Unmarked path values are required by the path itself.
- `API` authentication means either `X-Api-Key` or `Authorization: Bearer <token>`. `Signer` means the `signer-access-code` query parameter. A Signer call sends that code and no API key or bearer token, and an empty code is rejected with `errors.ErrInvalidInput` before any request. `Public` means no API credential. An OAuth access token is an `API` credential and must travel as `Authorization: Bearer`; it is refused as `X-Api-Key` or in the query string.
- Unless a row says binary, a successful response is JSON `{status: integer, message: string, data: ...}`. The SDK unwraps `data`. “Envelope only” is `{status, message}` with no documented `data`. The four OAuth operations are the exception: they answer with flat OAuth JSON and are never wrapped.
- Paginated SDK results contain `Data` plus values decoded from `X-Pagination-Current-Page`, `X-Pagination-Total-Count`, `X-Pagination-Page-Count`, and `X-Pagination-Per-Page`.
- Listed errors are the response codes declared for that operation. Non-2xx JSON failures become `*errors.APIError`; transport failures become `*errors.NetworkError`. Unsafe cross-origin mutation redirects wrap `errors.ErrUnsafeRedirect` and are never retried.
- Responses carry `X-Rate-Limit-Limit`, `X-Rate-Limit-Remaining` and `X-Rate-Limit-Reset` (seconds); past the limit the API answers `429` with `Retry-After` (seconds). `(*errors.APIError).RateLimit()` reads them.
- Request and response field names below are the wire-format JSON names. The [response payload reference](#response-payload-reference) expands every reusable response model.
- Contract-tracking and identity-verification operations and webhook deletion by URL are served in production; the sandbox deployment can return route-level 404s. Sandbox endpoint creation omits `secret`; API-key callers retrieve it with `GetEndpointSecret`.

### OAuth — 4 operations

These are the only operations outside the `{status, message, data}` envelope: they
return flat OAuth JSON so that a standard OAuth client library finds
`access_token` or `error` at the top level. They live in the `oauth` package
rather than on `client`, because an integration calls them before it has a client.
Token and revocation requests are sent `application/x-www-form-urlencoded`, per
RFC 6749 and the `client_secret_post` authentication method the server advertises.
They are sent once: the SDK never follows a redirect from either endpoint and
returns the `3xx` as an `*oauth.Error`, and the request carries no `GetBody`, so
the transport cannot resend the form on its own.

## Routes without a published contract

The reference mentions `POST /v1/signers/certificate/start` and
`POST /v1/signers/certificate/complete` in the description of the signing
operation, as the route a signer whose verification method is
`DigitalCertificate` must take instead of `POST /v1/documents/{documentId}/assignments/{assignmentId}`.

## Assignment verification and notification

Each assignment signer can specify how identity is verified and how the invitation is delivered. If both fields are omitted, both default to `Email`. Supplying only one lets the API infer the other. Only one notification method is accepted per signer.

| Verification method | Allowed notification | Requirements | Cost |
| --- | --- | --- | ---: |
| `Email` | `Email` | Signer email | 0 credits |
| `Whatsapp` | `Whatsapp` | Signer WhatsApp number and paid subscription | 0 credits for verification; 0.45 credits for notification |
| `DigitalCertificate` | `Email` or `Whatsapp` | `method: "virtual"`, enabled Digital Certificate feature, signer `government_id`, and the signer alone in its signing step | 0.5 credits plus notification cost |
| `IdDocumentFaceMatchBasic` | `Email` or `Whatsapp` | Identity verification feature, full name, and valid CPF in `government_id` | Plan-specific verification fee plus notification cost; estimate before sending |

`models.VerificationMethodEmail`, `VerificationMethodWhatsApp`, `VerificationMethodDigitalCertificate`, `VerificationMethodIDDocumentFaceMatchBasic`, `NotificationMethodEmail`, and `NotificationMethodWhatsApp` are the exact codes; they are untyped constants and assign to the `string` fields on `SignerReference`, `TemplateSigner`, and `EstimateAssignmentCostSigner`.

`Email` and `Whatsapp` verification cost only their notification. `Whatsapp` verification requires that channel's 0.45-credit notification. `DigitalCertificate` adds 0.5 credits per signer under `SignatureDigitalCertificate`; `IdDocumentFaceMatchBasic` adds the plan's verification fee under `VerificationIdDocumentFaceMatchBasic`. Charges apply at assignment creation; the estimate returns the exact total and breakdown.

A `DigitalCertificate` signer signs with their own ICP-Brasil certificate — A1 in software or A3 on a token or smart card — through the Web PKI browser extension, which produces a qualified PAdES signature. `government_id` must hold a CPF or CNPJ: a CPF requires that person's own certificate (an e-CPF, or an e-CNPJ naming them as legal representative), and a CNPJ requires an e-CNPJ for that company. Such a signer cannot use `client.Assignments.Sign`, which rejects them with 400; their signature comes from the two-step exchange in [Routes without a published contract](#routes-without-a-published-contract), and once the document closes its `pades` artifact carries the result.

The certificate exchange completes the virtual assignment item, so every `DigitalCertificate` signer requires `method: "virtual"`. `Assignments.Create` and the deprecated `EstimateCost` return `errors.ErrDigitalCertificateRequiresVirtual` before a request when the method is collect, missing, or unknown. `EstimateCostWithRequest` accepts an omitted method and rejects an explicitly non-virtual method for certificates. Send the intended method to obtain a matching estimate. The sentinel wraps `errors.ErrInvalidInput`. Template requests derive their method from placed fields; when a template signer uses `DigitalCertificate`, `CreateFromTemplate` and `EstimateCostFromTemplate` read the template detail and return the same sentinel if a page has fields assigned to a signing role. Fields on an `Editor` role are filled before signing and permit certificates.

When any `signers[].step` is supplied, every signer needs a positive step and the steps must be contiguous from 1. Signers in one step act in parallel; the next step is notified only after the preceding step completes. Use `EstimateCostWithRequest` before `Create` to obtain the account-specific document and credit totals.

## Response payload reference

The OpenAPI response components generally do not declare `required` arrays, so the field lists below describe the complete declared shape without implying that every field is populated by every endpoint. `null` is shown where the schema explicitly permits it. The Go `models.Timestamp` decoder accepts either the documented date-time string or a numeric timestamp returned by some live responses.

### Envelope and authentication payloads

- **Envelope**: `{status: integer, message: string}` plus the operation-specific `data` documented above.
- **ErrorEnvelope**: `{status: integer, message: string, data: object or null}`. `errors.APIError` also retains the HTTP status, response headers, optional top-level `code`, and `errors: [{field: string or null, code: string, message: string}]`. Account-deletion 400 responses add `restrictions: [{code: "ActivePaidSubscription" or "PendingDocuments", message: string, account_ids: []string}]`.
- **`errors.ErrDigitalCertificateRequiresVirtual`**: stable local error for a `DigitalCertificate` signer on a non-virtual assignment; it wraps `errors.ErrInvalidInput` and no estimate, invitation, or charge request is sent.
- **`models.AuthenticationResult`** (`AuthSession`): `{access_token: string, user: AuthUser, accounts: []AuthAccount}`. A login that needs a second factor carries `mfa_token: string` for `VerifyMFA`.
- **`models.MFAStatus`**: `{methods: []{id: string, type: string ("Totp"), label: string, confirmed_at: date-time, last_used_at: date-time or null}, recovery_codes_remaining: integer}`.
- **`models.TOTPEnrollment`**: `{id: string, secret: string (base32), provisioning_uri: string (otpauth://)}`.
- **`models.User`** (`AuthUser`): `{id: string, name: string, email: email, telephone: string or null, government_id: string or null, is_email_verified: boolean, has_accepted_terms: boolean, is_password_set?: boolean, created_at: date-time, to_be_deleted_at: date-time or null}`. `is_password_set` is used by webhook user subjects. Nullable `telephone` and `government_id` decode to empty Go strings.
- **`models.WorkspaceListItem`** (`AuthAccount`): `{id: string, name: string, roles: []string, is_delete_allowed: boolean, created_at: date-time}`.
- **`models.APIKeyResult`** (`ApiKey`): `{api_key: string or null}`.
- **`models.EmailResult`**: `{email: email}`.

### OAuth payloads

None of these are wrapped in the envelope.

- **`oauth.Token`**: `{access_token: string, issued_token_type?: string (RFC 8693 only), token_type: "Bearer", expires_in: integer, refresh_token: string (only with `offline_access`), scope: string (space-separated, what was actually granted), id_token: string (only with `openid`)}`. The SDK adds `Expiry`, computed from `expires_in` when the token was issued, and persists with the rest.
- **`oauth.Error`**: `{error: string, error_description: string}` plus the HTTP status. `oauth.ErrorCode(err)` reads the code; `access_denied`, `invalid_client`, `invalid_grant`, `invalid_request`, `invalid_scope`, `invalid_target`, `unsupported_grant_type`, and `unsupported_response_type` have constants.
- **`oauth.UserInfo`**: `{sub: string, name: string or null, email: email or null, email_verified: boolean or null}`.
- **`oauth.ProtectedResourceMetadata`**: `{resource: URI, authorization_servers: []URI, scopes_supported: []string, bearer_methods_supported: ["header"]}`.
- **`oauth.AuthorizationServerMetadata`**: `{issuer, authorization_endpoint, token_endpoint, revocation_endpoint, userinfo_endpoint, jwks_uri, scopes_supported, response_types_supported, grant_types_supported, code_challenge_methods_supported, token_endpoint_auth_methods_supported, authorization_response_iss_parameter_supported}`.
- A call an OAuth token lacks permission for is `403` with `WWW-Authenticate: Bearer error="insufficient_scope", scope="…"`. `errors.InsufficientScope(err)` returns that scope; a `403` without the header has another cause.

### Account and statistics payloads

- **`models.Account`**: `{resource: string, id: string, name: string, primary_color: string or null, secondary_color: string or null, notification_sender_type: "User" or "Account", roles: []string, is_delete_allowed: boolean, limits?: AccountLimits, created_at: date-time}`.

- **`models.DocumentStatsRow`**: `{period: YYYY-MM or YYYY-MM-DD, documents_uploaded: integer, documents_sent: integer, signature_requests: integer, signature_requests_notification_email: integer, signature_requests_notification_whatsapp: integer, signature_requests_notification_bypass: integer, signature_requests_verification_email: integer, signature_requests_verification_whatsapp: integer, signature_requests_verification_bypass: integer, signature_requests_verification_digital_certificate: integer, signature_requests_viewed: integer, signature_requests_completed: integer, documents_certified: integer}`. ### Signer and assignment payloads

### Webhook signatures

An endpoint with `signing_enabled` adds `webhook-signature`, following [Standard Webhooks](https://www.standardwebhooks.com): one or more space-separated `v1,<base64>` entries, each `base64(HMAC-SHA256(key, "{webhook-id}.{webhook-timestamp}.{raw body}"))`, where `key` is the base64-decoded part of the secret after `whsec_`. `NewWebhookVerifier(secret).VerifyRequest(r.Header, body)` checks the signature in constant time and rejects a `webhook-timestamp` more than `WebhookTolerance` (five minutes) from the local clock. A rotated secret applies to every delivery sent after the rotation.

Consumers should deduplicate on the `webhook-id` header, accept unknown JSON fields and event names, and not assume ordering between `assignment_created` and `document_metadata_ready`.
