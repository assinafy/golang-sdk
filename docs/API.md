# Assinafy API v1 mapping

This reference maps the Assinafy Go SDK to all 89 operations in the current [API documentation](https://api.assinafy.com.br/v1/docs) and [OpenAPI description](https://api.assinafy.com.br/v1/docs/openapi.json). It was last checked against OpenAPI `3.0.0`, API version `1.0.0`, on 2026-08-20.

## Conventions

- Paths include `/v1` as shown by the API. SDK resource methods use paths relative to `ClientOptions.BaseURL`, which already includes `/v1`.
- Every `{name}` in a path is a required string path parameter. Passing an empty account ID to an account-scoped SDK method uses `ClientOptions.AccountID`.
- `*` marks a required body field. `?` marks an optional body or query field. Unmarked path values are required by the path itself.
- `API` authentication means either `X-Api-Key` or `Authorization: Bearer <token>`. `Signer` means the `signer-access-code` query parameter. `Public` means no API credential.
- Unless a row says binary, a successful response is JSON `{status: integer, message: string, data: ...}`. The SDK unwraps `data`. “Envelope only” is `{status, message}` with no documented `data`.
- Paginated SDK results contain `Data` plus values decoded from `X-Pagination-Current-Page`, `X-Pagination-Total-Count`, `X-Pagination-Page-Count`, and `X-Pagination-Per-Page`.
- Listed errors are the response codes declared for that operation. Non-2xx JSON failures become `*errors.APIError`; transport failures become `*errors.NetworkError`.
- Request and response field names below are the wire-format JSON names. The [response payload reference](#response-payload-reference) expands every reusable response model.

## Response payload reference

The OpenAPI response components generally do not declare `required` arrays, so the field lists below describe the complete declared shape without implying that every field is populated by every endpoint. `null` is shown where the schema explicitly permits it. The Go `models.Timestamp` decoder accepts either the documented date-time string or a numeric timestamp returned by some live responses.

### Envelope and authentication payloads

- **Envelope**: `{status: integer, message: string}` plus the operation-specific `data` documented above.
- **ErrorEnvelope**: `{status: integer, message: string, data: object or null}`. `errors.APIError` also retains the HTTP status code.
- **`models.AuthenticationResult`** (`AuthSession`): `{access_token: string, user: AuthUser, accounts: []AuthAccount}`.
- **`models.User`** (`AuthUser`): `{id: string, name: string, email: email, telephone: string or null, government_id: string or null, is_email_verified: boolean, has_accepted_terms: boolean, created_at: date-time, to_be_deleted_at: date-time or null}`. For source compatibility, nullable `telephone` and `government_id` decode to empty Go strings.
- **`models.WorkspaceListItem`** (`AuthAccount`): `{id: string, name: string, roles: []string, is_delete_allowed: boolean, created_at: date-time}`.
- **`models.APIKeyResult`** (`ApiKey`): `{api_key: string or null}`.
- **`models.EmailResult`**: `{email: email}`.

### Account and statistics payloads

- **`models.TemplateFieldPlacement`**: `{id: string, field_id: string, role_id: string, label: string, display_settings: any JSON value, created_at: date-time, updated_at: date-time}`.
- **`models.TemplateRole`**: `{id: string, name: string, assignment_type: string, created_at: date-time, updated_at: date-time}`.

### Webhook payloads

- **`models.WebhookSubscription`**: `{events: []string, is_active: boolean, url: string or null, email: string or null, updated_at: date-time or null}`.
- **`models.WebhookEventType`**: `{id: string, description: string}`.
- **`models.WebhookDispatch`**: `{resource: string, id: string, event: string, activity_id: integer, endpoint: string or null, payload: object or null, delivered: boolean, http_status: integer or null, response_body: string or null, error: string or null, created_at: date-time, updated_at: date-time}`.

### Nested request object

- **`models.DisplaySettings`**: required `left: number >= 0`, `top: number >= 0`, `width: number > 0`, `height: number > 0`, and `fontSize: number > 0`; optional `fontFamily: string` and `backgroundColor: string`. It uses Assinafy's 150-DPI page coordinate system. Existing request fields remain typed as `any` for source compatibility, and callers may pass this concrete type.
- **`models.UpdateFieldDefinitionRequest` regex states**: leave both `Regex` nil and `ClearRegex` false to omit `regex`; set `Regex` to send a string; set `ClearRegex` true to send JSON `null`. The null clear behavior is live-verified. The sandbox expects regular-expression strings in delimiter syntax.

## Compatibility extensions

These SDK capabilities are retained for compatibility or verified live behavior. They are not operations or features declared by the current OpenAPI document and are not included in the 89-operation count.

| SDK capability | Status and guidance |
| --- | --- |
| `client.Templates.Get(ctx, accountID, templateID)` | Calls `GET /accounts/{accountId}/templates/{templateId}`. The route is absent from the current OpenAPI and official endpoint index, but it was verified successfully in the sandbox on 2026-08-20 using an ID returned by the template list. Treat it as a live compatibility extension, not a documented operation. |
| `client.Authentication.SocialLoginURL(provider)` | Builds the browser URL for `/auth/authenticate`. That redirect route is absent from the current OpenAPI; the documented API operation is `SocialLogin` with an identity token. |
| `NewWebhookVerifier(secret).Verify(body, signature)` | Implements `hex(HMAC-SHA256(secret, body))`. The OpenAPI defines no signature header, secret, or HMAC algorithm. `ExtractEvent` is safe for payload decoding, but HMAC authenticity requires a separately agreed delivery contract. |
| `PublicDocuments.SendTokenWithRequest` legacy-sandbox retry | Sends an email-bearing official request first. It retries only an HTTP 400 whose API message mentions `channel`, using `{recipient: email, channel: "email"}`. `SendTokenByEmail` delegates to this method. The fallback is live-verified but is not the current OpenAPI request shape. |
| Document-tag names in `ReplaceTags` and `AppendTags` | The OpenAPI body describes tag IDs. The sandbox/live API also accepts names and creates missing names case-insensitively; this behavior has live integration coverage. Use IDs when strict OpenAPI portability matters. Template-document creation is different: its official `tags` field explicitly accepts names. |
| Extra multipart and model fields | `Documents.Upload` can send `name` and caller metadata parts; field create/update models and `ConfirmSignerDataRequest` retain additional live or historical fields. Only the operation-specific fields in the official tables above are portable under the current OpenAPI. |
| Shared `models.ListParams` fields | The shared type carries filters used by several resources. Set only the query fields listed for the chosen operation; non-listed filters are compatibility behavior, not part of that operation's current schema. |

## Deprecated and earlier call shapes

No earlier public method has been removed. The following methods are formally deprecated in Go documentation:

| Deprecated API | Replacement | Reason |
| --- | --- | --- |
| `PublicDocuments.Get` | `PublicDocuments.GetDocument` | The older method decodes a reduced public-document model; v1 documents a full `Document`. |
| `PublicDocuments.SendToken` | `PublicDocuments.SendTokenWithRequest` or `PublicDocuments.SendTokenByEmail` | The older request/response includes undocumented channel and result fields; v1 documents optional email and an envelope-only response. |
| `Assignments.EstimateCost` | `Assignments.EstimateCostWithRequest` | The older method accepts an assignment-creation body rather than the dedicated estimate body. |
| `Assignments.ResetExpiration` | `Assignments.ResetExpirationWithRequest` | The older nil-pointer form sends JSON null; the current schema permits omission but not null. |
| `Signers.AcceptTerms` | `Signers.AcceptTermsOnly` | The current response is envelope-only, so the older returned signer is zero-valued. |
| `Signers.ConfirmData` | `Signers.ConfirmDataAndGet` | The older method discards the documented signer response. |
| `Signers.UploadSignatureWithContentType` | `Signers.UploadSignature` or `Signers.UploadSignatureWithReuse` | v1 documents only an `image/png` body, with optional `type` and `reuse` queries. |
| `SignerDocuments.Search` | `SignerDocuments.SearchAll` | The current operation is non-paginated and only documents the `search` query. |
| `Fields.Validate` | `Fields.ValidateAuthenticated` | The current operation uses client authentication, not a signer access code. |
| `Fields.ValidateMultiple` | `Fields.ValidateMultipleAuthenticated` | The current operation uses client authentication, not a signer access code. |

Other earlier signatures remain supported but have exact-contract alternatives: `Assignments.GetSigningInfoWithTerms`, `Documents.DetachTagWithResult`, and `Tags.DeleteWithResult`. Prefer the exact variant when its extra request or response detail matters.
